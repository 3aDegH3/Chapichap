# وضعیت اولویت‌ها و Acceptance Criteria پنل مدیریت

## Must Have

همه موارد Must Have اسپرینت تکمیل شده‌اند:

- ورود امن مدیر و محافظت هم‌زمان Frontend و Backend
- داشبورد عملیاتی
- مدیریت محصولات، دسته‌بندی‌ها و تصاویر
- مدیریت سفارش، وضعیت، تاریخچه و یادداشت داخلی
- مشاهده و دانلود امن فایل‌های مشتری
- مدیریت درخواست طراحی و پیام تماس
- Role و Permission سمت سرور

## Should Have

همه موارد Should Have تکمیل شده‌اند:

- تاریخچه موجودی
- گزارش فعالیت مدیران
- مدیریت مشتریان
- عملیات گروهی خواندن پیام‌های تماس
- خروجی CSV فیلترشده سفارش‌ها

خروجی CSV در مسیر `GET /api/v1/admin/orders/export/csv/` قرار دارد و از پارامترهای `q`، `status`، `payment_status`، `delivery_method`، `date_from` و `date_to` پشتیبانی می‌کند.

## Could Have

موارد Could Have شرط تکمیل اسپرینت نیستند. اعلان سفارش جدید و چاپ خلاصه سفارش در نسخه فعلی وجود دارند؛ نمودار فروش، Dark Mode و Drag and Drop تصاویر برای اسپرینت بعدی باقی می‌مانند.

## خارج از اسپرینت

درگاه واقعی، پیامک واقعی، حسابداری، CRM کامل، گزارش مالی پیشرفته و اپلیکیشن موبایل ادمین عمداً وارد این تغییرات نشده‌اند.

## شواهد Acceptance Criteria

| معیار پذیرش | پیاده‌سازی و پوشش |
| --- | --- |
| ایجاد و ویرایش محصول | API، فرم مدیریت و تست ساخت محصول دارای گالری |
| تغییر قیمت و موجودی | API و فرم محصول، تاریخچه موجودی و Audit Log |
| جستجو و فیلتر سفارش | فیلتر مشترک فهرست و CSV، تست ترکیب شماره تماس و وضعیت |
| تغییر وضعیت سفارش | endpoint وضعیت و تست رفتاری |
| ثبت تاریخچه وضعیت | `OrderStatusHistory` همراه مدیر تغییر‌دهنده و تست |
| مشاهده فایل مشتری | Preview/Download امن، فایل متصل به سفارش و Audit Log |
| ثبت یادداشت داخلی | سفارش، درخواست طراحی و پیام تماس |
| مدیریت طراحی و پیام | فهرست، جزئیات، وضعیت، پاسخ، یادداشت و عملیات گروهی |
| منع دسترسی کاربر عادی | Permission سمت سرور و تست ماتریسی تمام دامنه‌های مدیریت |

تست‌های اجرایی در `apps.admin_panel.tests` قرار دارند و با تنظیمات مستقل SQLite اجرا می‌شوند.
